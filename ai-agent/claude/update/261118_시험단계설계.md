# 시험 단계 설계 (객관식 → 주관식 승격)

**파일 위치**: `ai-agent/claude/update/261118_시험단계설계.md`
**작성일**: 2026-11-18
**버전**: v1.0 (승인, 261118 결정 반영)

> 결정 (261118): D1 객관식 우선으로 요구사항 변경 (FR-038, ADR-012). D2, D3, D5, D6, D7 기본안. D4 변경: 주관식 오답 시 객관식으로 강등. D8 변경: 승격 후 주관식 문제의 20% 를 객관식으로 섞음. D9 원형만 인정.
**설명**: 시험을 처음에는 객관식으로 자주 내고, 단어를 충분히 맞히면 주관식(직접 입력)으로 승격하는 방식의 세부 규칙과 판단 항목을 정리한다. 구현 전 결정 사항을 확정하기 위한 문서다.

---

## 1. 배경과 요구사항 충돌

- 요청: 시험을 주관식으로 바로 띄우지 말고, 객관식을 많이 노출한 뒤 많이 맞히면 주관식으로 승격한다.
- 충돌: 현재 요구사항은 1차 시험을 주관식(직접 입력)으로 확정했다.
  - FR-033 (답은 사용자가 직접 입력), FR-038 (뜻을 보고 영단어를 직접 입력)
  - OI-07 (직접 입력 확정), ADR-004 (1차 시험은 뜻 보고 영단어 입력)
- 이 설계가 채택되면 FR-038 과 ADR-004 를 "단계별 출제 (객관식 → 주관식)"로 고쳐야 한다. 요구사항 변경이므로 사용자 승인이 필요하다.
- 채점 규칙 (FR-033, 앞뒤 공백과 대소문자 무시)은 주관식 단계에서 그대로 유지한다.

## 2. 제안 설계

### 2.1 단계 모델

| 단계 | 출제 형식 | 정답 판정 |
|------|----------|----------|
| `mc` (객관식) | 영단어를 보여 주고 뜻 4지선다 (정답 1 + 오답 3) | 선택한 보기가 정답인지 |
| `typed` (주관식) | 뜻을 보여 주고 영단어 직접 입력 | 현재 채점 규칙 (FR-033) |

- 단어는 `mc` 로 시작한다. 승격 전까지는 `mc` 로만 출제한다.
- 한 단어의 단계는 `mc` → `typed` 단방향이 기본이다 (강등 여부는 3절 결정 항목).

### 2.2 객관식 보기 (오답) 만들기

- 정답은 단어의 뜻 (`meaning_ko`). 오답 3개는 다른 단어의 뜻에서 뽑는다.
- 오답 후보 조건:
  - 정답 단어와 다른 단어
  - 뜻 문자열이 정답과 같지 않음
  - 기본은 같은 난이도 (`level`) 안에서 뽑는다 (보기 풀 결정은 3절)
- 후보가 3개보다 적으면 그 단어는 이번 회차에서 `typed` 로 대체 출제한다. 객관식 불가로 보고 승격 판정에는 넣지 않는다.
- 보기 순서는 매번 섞는다.

### 2.3 승격 규칙 (기본안)

- 승격 카운트는 `mc` 단계 정답 수로 센다.
- 같은 날 여러 번 맞혀도 **하루 최대 1회**만 센다 (벼락치기 방지). 기본안.
- **연속 3일 정답** (기본안) 이면 `typed` 로 승격한다. 중간에 틀리면 연속 카운트를 0으로 되돌린다.
- 승격 시각 `promoted_at` 을 기록한다. 승격 후에는 되돌리지 않는다 (강등 결정에 따름).

### 2.4 출제 구성 (하루 시험)

- 문제 수는 설정 `exam_size` (5~20, 기본 10) 를 따른다.
- 후보 = 오늘 목록 + 오늘 재노출 대상 (기존 P4 와 같음).
- 후보 중 `mc` 단계 단어는 객관식, `typed` 단계 단어는 주관식으로 낸다.
- 객관식 비율 상한 (기본안): 전체 문제의 70%. 나머지는 주관식 단계 단어로 채운다. `typed` 단어가 부족하면 객관식으로 채운다.
- 객관식 비율과 상한은 3절 결정 항목.

### 2.5 채점과 기록

- 객관식: 선택한 보기의 뜻이 정답이면 `is_correct = 1`.
- 주관식: 현재 규칙 그대로 (FR-033).
- `exam_attempt` 에 `question_type` (`mc` / `typed`) 을 추가해 기록한다. 보기 목록 (스냅샷)은 저장하지 않는다.
- 승격 카운트와 단계는 별도 테이블 `word_stage` 에 저장한다 (2.6).
- 시험 결과는 재노출 일정 (`review_schedule`) 을 바꾸지 않는다 (FR-037 유지).

### 2.6 데이터 변경 (DB 버전 4 → 5)

| 테이블 | 변경 | 내용 |
|--------|------|------|
| `word_stage` (신규) | `word_id` (PK, FK), `stage` (`mc`/`typed`), `mc_streak` (정수), `last_counted_date` (날짜), `promoted_at` (nullable) | 단어별 단계와 승격 카운트 |
| `exam_attempt` | `question_type` 열 추가 (기존 행은 `typed`) | 객관식/주관식 구분 |

- 마이그레이션은 `MIGRATION_4_5` 로 작성한다. 기존 시험 이력은 `typed` 로 본다.
- `word_stage` 행이 없는 단어는 `mc` 로 취급한다.

## 3. 판단이 필요한 항목

| 번호 | 항목 | 기본안 | 선택지 |
|------|------|--------|--------|
| D1 | 요구사항 변경 (FR-038, ADR-004, OI-07) | 단계별 출제로 변경 | 변경 / 1차는 주관식 유지 |
| D2 | 승격 기준 | 연속 3일 정답 | 연속 3일 / 누적 5회 / 누적 10회 |
| D3 | 하루 카운트 | 하루 최대 1회 | 하루 최대 1회 / 횟수 제한 없음 |
| D4 | 주관식에서 틀렸을 때 | 주관식 유지 (강등 없음) | 유지 / 객관식으로 강등 |
| D5 | 객관식 보기 개수 | 4지선다 | 3지선다 / 4지선다 |
| D6 | 오답 보기 풀 | 같은 난이도 | 같은 난이도 / 전체 |
| D7 | 객관식 비율 상한 | 70% | 50% / 70% / 설정 가능 |
| D8 | 승격 후 객관식 재출제 | 주관식만 출제 | 주관식만 / 가끔 객관식 섞기 |
| D9 | 주관식 정답 형태 (FR-034, 2차) | 현재처럼 원형만 인정 | 유지 (변경 없음) |

## 4. 구현 범위 (승인 후)

1. 요구사항 명세, 기획서, ADR 에 D1 결과를 반영한다.
2. `word_stage` 와 `question_type` 을 추가하고 `MIGRATION_4_5` 를 작성한다.
3. 보기 생성 (오답 3개 추출)과 채점 규칙을 domain 에 둔다. 단위 테스트를 작성한다.
4. 시험 출제 (P4)를 단계별로 나누고, 승격 판정 (P5 뒤)을 추가한다.
5. 시험 화면에 객관식 보기 선택 UI를 추가한다.
6. 기기에서 승격 흐름 (날짜를 바꿔 연속 일수 확인은 단위 테스트로 대체)을 확인한다.
