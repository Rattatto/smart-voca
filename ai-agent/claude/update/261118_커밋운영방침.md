# 커밋 운영 방침 (세션 간 커밋 분리)

**파일 위치**: `ai-agent/claude/update/261118_커밋운영방침.md`
**작성일**: 2026-11-18
**버전**: v1.0 (승인, 사용자 방침)
**설명**: 같은 저장소를 기능 구현 세션과 디자인 세션이 함께 쓰므로, 커밋과 푸시 시점과 범위를 정한다.

---

## 1. 배경

- 기능 구현 세션과 디자인 세션이 `C:\dev\smart-voca` 를 함께 사용한다.
- 2026-11-18 푸시 때 디자인 세션이 만든 커밋 `a8d8c86` (`Theme.kt`, ADR-013 개정)이 기능 커밋과 함께 올라갔다. 두 세션의 커밋 시점이 정해져 있지 않아서 생긴 일이다.
- 디자인 세션의 미커밋 변경 (`Theme.kt`, ADR 파일, `261118_디자인/`, 디자인 메모, `ai-agent/uploads/`)은 기능 커밋에 섞이면 안 된다.

## 2. 대안

| 안 | 내용 | 장단점 |
|----|------|--------|
| A | 같은 `main` 에서 세션별로 커밋 범위와 시점을 약속한다 | 추가 설정 없음. 약속을 어기면 다시 섞인다 |
| B | `feature/*`, `design/*` 브랜치로 나눈다 | 섞일 위험이 적다. 병합 관리가 필요하다 |

## 3. 결정 (승인)

결정: **A 를 우선 적용한다.** 브랜치 분리 (B)는 디자인 작업이 커져서 파일이 자주 겹치면 다시 검토한다.

1. **커밋 범위:** 커밋 전에 `git status` 로 이번 세션이 수정한 파일만 골라 `git add` 한다. 다른 세션의 파일은 스테이징하지 않는다.
2. **세션 간 같은 파일:** 두 세션이 같은 파일을 고쳤으면 커밋 전에 사용자에게 확인한다.
3. **커밋 시점:** 커밋은 사용자 승인 후 진행한다 (CLAUDE.md 자동 실행 원칙 유지).
4. **푸시 시점:** 푸시는 기기 확인 결과를 보고한 뒤 사용자 승인을 받아 진행한다. 푸시는 그 시점까지의 커밋 전체가 대상이므로, 푸시 전에 `git log origin/main..main` 으로 포함 커밋을 보여 준다.
5. **디자인 세션 커밋:** 디자인 세션의 커밋 시점은 사용자와 협의해 정한다. 기능 세션은 디자인 세션의 미커밋 파일을 건드리지 않는다.

## 4. 결정 근거

- 커밋 이력이 세션별로 읽히도록 해서 나중에 기능과 디자인 변경을 추적하기 쉽게 한다.
- 승인과 푸시를 단계로 나눠서, 기기에서 확인되지 않은 변경이 원격에 올라가는 일을 줄인다.
