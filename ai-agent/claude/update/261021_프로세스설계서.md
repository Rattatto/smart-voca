# Smart Voca 프로세스 설계서

**파일 위치**: `ai-agent/claude/update/261021_프로세스설계서.md`
**작성일**: 2026-10-21
**버전**: v1.1 (초안)
**설명**: 일일 단어 선정, 재노출, 시험 출제와 채점, 설정 반영의 단계별 규칙을 정의한다. 모든 FR 을 이 문서의 절에 연결한다 (11절). 소스 코드는 포함하지 않는다.

---

## 1. 공통 규칙

- "오늘"은 기기 로컬 날짜다.
- 동사 비중(FR-012, FR-032, FR-042)은 품사(OI-12) 확보 전까지 적용하지 않는다. 설정값은 저장만 한다.
- 빈칸 문장 시험(FR-030, FR-034)은 2차 버전 범위이므로 이 문서에 포함하지 않는다.
- 학습 통계 (FR-050, FR-051)는 2차 버전 범위다 (OI-05). 정의만 10절에 남긴다.
- 모든 절차는 서버 없이 기기 안에서 실행된다 (NFR-001).

## 2. P1. CSV 가져오기 (FR-001~005)

| 단계 | 처리 | 실패 시 | FR |
|------|------|---------|----|
| 1 | 파일을 UTF-8 로 읽는다 (BOM 허용) | 읽기 실패 → 중단, 사유 표시 | FR-001 |
| 2 | 헤더를 검사한다. 필수 열 `word, meaning_ko, freq_rank, level` 확인 | 누락 열 이름을 표시하고 중단 | FR-002 |
| 3 | 행마다 필수 값과 형식을 검증한다 | 해당 행 건너뜀, 행 번호와 사유 기록 | FR-003 |
| 4 | 유효한 행을 `freq_rank` 기준으로 저장한다. 같은 순위는 갱신한다 | 저장 실패 → 전체 롤백 | FR-001, FR-005 |
| 5 | 결과(저장 개수, 건너뜀 개수, 건너뜀 목록)를 표시한다 | | FR-003 |

**적재 규모 (FR-005):** 적재 상한은 두지 않는다. 2,000개 이상도 같은 절차로 적재한다. 기준 성능은 NFR-003 (2,000개 30초 이내).

**중복 기준 (FR-004, 보류):** 품사 (`pos`) 가 확보되기 전까지 `freq_rank` 를 중복 기준으로 쓴다. `word` + `pos` 기준은 품사 확보 후 적용한다 (OI-12, #7).

**구현 현황 (2026-11-11, #1):** 1~5 단계 구현 및 기기 검증 완료. 4 단계 중복 기준은 `freq_rank` 만 적용.

## 3. P2. 일일 목록 생성 (FR-010~015)

**입력:** 오늘 날짜, 설정 (`daily_count`, `level_filter`)

> 구현 현황 (2026-11-11, #2): 단계 1, 3 (신규 단어 부분), 4 (신규 단어 부분), 5, 6 을 구현했다. 설정 값은 DataStore 에서 읽는다 (#5). 재노출 후보 (단계 2)와 학습 완료 제외 (단계 3 의 `study_record` 조건)는 #3 에서 붙인다. 기능어는 단계 3 에서 제외하고 TIP 칸에 보여 준다 (3절 P2-1).

1. `daily_list` 에 오늘 날짜 행이 있으면 그대로 보여 주고 종료 (FR-013).
2. 재노출 후보를 찾는다 (FR-014).
   - 조건: `review_schedule.next_review_date` ≤ 오늘
   - 정렬: `next_review_date` 오름차순, 같으면 `freq_rank` 오름차순
   - 상한: `floor(daily_count × 0.3)` 개 (FR-014, 확정 OI-08)
3. 신규 단어 후보를 찾는다.
   - 조건: `study_record` 에 없고, `level_filter` 에 맞는 단어 (FR-011). 재노출 후보는 제외
   - 조건: 기능어 목록 (관사, 조동사, be·have·do, 전치사, 접속사, 대명사·한정사, 기능 부사)에 있는 단어는 제외하고 TIP 칸으로 보낸다
   - 정렬: `freq_rank` 오름차순 (빈도가 높은 단어 우선)
4. 목록을 채운다.
   - 재노출 후보를 먼저 최대 상한까지 넣는다.
   - 나머지 자리는 신규 단어로 채운다.
   - 신규 단어가 부족하면 남은 재노출 후보를 상한을 넘겨 넣는다. 그래도 부족하면 목록을 짧게 둔다.
5. `daily_list` 에 저장한다. `source`, 설정 스냅샷 (`daily_count`, `level_filter`), 노출 시각 `shown_at` 을 함께 저장한다 (FR-015). 노출 시각은 목록을 만든 시각과 같다.
6. `position` 순서로 보여 준다. 재노출 단어와 신규 단어의 순서는 재노출 먼저.

**예외:** 단어가 하나도 없으면 "가져온 단어가 없습니다. CSV 를 먼저 가져오세요"를 표시하고 목록을 저장하지 않는다.

### P2-1. 기능어 TIP (FR-010 관련, 설계 결정 2026-11-11)

- 기능어는 목록에 들어가지 않는다. 목록 옆 "오늘의 TIP" 칸에 날짜마다 하나씩 보여 준다.
- TIP 선택: 날짜의 epoch day 를 기능어 개수로 나눈 나머지 (같은 날은 같은 TIP).
- 예문이 없는 단어는 뜻만 보여 준다 (예문 열이 비어 있으면 예문 줄을 만들지 않는다).

## 4. P3. 학습 완료와 재노출 일정 (FR-020~023)

**입력:** 단어 ID, 오늘 날짜

1. `study_record` 에 학습 행을 추가한다 (FR-020).
2. 일정을 갱신한다.
   - `review_schedule` 에 행이 없으면 step 0 으로 새로 만든다.
   - 있으면 step 을 1 올린다.
   - 간격 표에서 다음 날짜를 계산한다 (FR-021). step 0 → 1일, 1 → 3일, 2 → 7일, 3 → 14일, 4 → 30일.
   - 올린 step 이 5 이상이면 `next_review_date` 를 비우고 종료한다 (FR-023, 30일 이후 재노출 없음).
3. 같은 날 같은 단어를 두 번 완료해도 일정은 한 번만 올린다. 이미 오늘 완료된 기록이 있으면 일정을 바꾸지 않는다 (PR-03).

**시험 결과와의 관계:** 이 프로세스는 학습 완료 버튼으로만 실행된다. 시험 결과는 입력되지 않는다 (FR-022, FR-037).

---

## 5. P4. 시험 출제 (FR-031, FR-035, FR-038)

**입력:** 오늘 날짜, 설정 `exam_size` (FR-043, 범위 5~20, 기본 10)

1. 출제 후보 = 오늘 `daily_list` 의 단어 + `review_schedule` 에서 오늘 재노출 대상인 단어 (중복 제거).
2. 후보가 `exam_size` 보다 적으면 후보 전체를 출제한다.
3. 후보에서 `exam_size` 개를 무작위로 뽑는다. 순서도 무작위로 섞는다 (FR-035).
4. 각 문제는 `meaning_ko` 를 보여 주고, 사용자가 영단어를 입력한다 (FR-038).

**예외:** 후보가 없으면 "오늘 시험할 단어가 없습니다"를 표시한다.

## 6. P5. 채점과 시험 이력 (FR-033, FR-036, FR-037)

1. 입력값과 정답 `word` 를 비교한다.
   - 앞뒤 공백을 제거한다.
   - 대소문자를 무시한다.
   - 그 외 문자는 그대로 비교한다.
2. 정답이면 `is_correct = 1`, 아니면 `0`.
3. `exam_attempt` 에 기록한다 (FR-036). 저장 항목은 다음과 같다.
   - 날짜 (`date`)
   - 단어 (`word_id`)
   - 제시한 뜻 (`shown_meaning`)
   - 입력값 (`user_input`)
   - 정답 여부 (`is_correct`)
4. 채점 결과는 재노출 일정에 반영하지 않는다 (FR-037).
5. 오답 시 정답 단어를 화면에 보여 준다.

## 7. P6. 설정 저장과 반영 (FR-040~045)

| 단계 | 처리 | FR |
|------|------|----|
| 1 | 입력 값이 범위 안인지 확인한다 (아래 표) | FR-040~043 |
| 2 | DataStore 에 저장한다 | FR-044 |
| 3 | 반영 시점: 오늘 `daily_list` 가 이미 있으면 그 목록은 바꾸지 않는다. 설정은 다음에 목록을 만들 때 적용한다 | FR-045 |

**설정 항목과 범위**

| 항목 | 범위 | 기본값 | 적용 상태 | FR |
|------|------|--------|-----------|----|
| 일일 노출 개수 `daily_count` | 5~30, 1 단위 | 10 | 적용 (P2) | FR-040 |
| 난이도 `level_filter` | 기초, 중급, 심화, 전체 | 전체 | 적용 (P2) | FR-041 |
| 동사 비중 | 30~90%, 10% 단위 | 60% | 저장만 (품사 확보 후 적용) | FR-042 |
| 시험 문제 수 `exam_size` | 5~20, 1 단위 | 10 | 적용 (P4) | FR-043 |

**확정 해석 (PR-01, 261021):** 오늘 목록이 아직 없는 상태에서 설정을 바꾸면 오늘 목록부터 새 설정이 적용된다. 오늘 목록이 이미 만들어진 뒤 바꾸면 다음 날부터 적용된다.

**저장 실패 시:** 저장 값이 범위를 벗어나 있으면 기본값으로 읽는다. 앱을 다시 켜도 설정 값은 유지된다 (FR-044).

## 10. 2차 범위 정의 (FR-050, FR-051)

**학습 통계 (FR-050, 2차)**
- 학습 일수: `study_record` 의 `study_date` 중 서로 다른 날짜 수
- 시험 정답률: `exam_attempt` 의 `is_correct` 평균 (전체 기간)
- 학습 단어 수: `study_record` 의 `word_id` 중 서로 다른 값 수

**오답 목록 (FR-051, 2차)**
- 단어별 오답 횟수: `exam_attempt` 에서 `is_correct = 0` 인 행 수를 `word_id` 별로 센다
- 횟수 내림차순, 같으면 `freq_rank` 오름차순

**이번 단계에서 하지 않는 것:** 화면 설계, 통계 기간 선택 (2차에서 정한다).
