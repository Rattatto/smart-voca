## 2. 결정 기록 (ADR 초안, 승인 전)

### ADR-014. 플랫폼을 웹 브라우저 앱(PWA)으로 변경 (ADR-001 대체)
- **배경**: 기획이 바뀌어 설치 없이 인터넷 브라우저에서 쓰는 방식이 필요해짐.
- **대안**: (1) 안드로이드 유지, (2) Compose Multiplatform 웹 (Kotlin 일부 재사용), (3) React + TypeScript, (4) 순수 HTML/JS.
- **결정 근거**: Compose 웹은 아직 베타이고 Room 을 웹에서 쓸 수 없어 재사용 이점이 작다. React 는 화면을 컴포넌트 함수로 나누는 방식이 Compose 와 비슷해서 기존 화면 설계를 옮기기 쉽고 자료가 가장 많다. TypeScript 는 Kotlin 처럼 타입 검사를 해 주므로 데이터 모델 오류를 빌드 단계에서 잡는다.

### ADR-015. 로컬 저장은 IndexedDB (Dexie) (ADR-002, ADR-003 대체)
- **배경**: 브라우저에는 Room/SQLite, DataStore 가 없다.
- **대안**: (1) localStorage 만 사용, (2) IndexedDB 직접 사용, (3) Dexie, (4) SQLite WASM.
- **결정 근거**: localStorage 는 용량이 약 5MB 이고 문자열만 저장해서 단어 2,000개 이상과 시험 기록을 담기에 부족하다. IndexedDB 원본 API 는 콜백 방식이라 코드가 길다. Dexie 는 Room 처럼 테이블과 인덱스, 버전별 마이그레이션(`db.version(n).upgrade`)을 선언할 수 있다. SQLite WASM 은 파일이 크고 설정이 복잡하다. 설정 값도 같은 DB 의 `settings` 테이블에 저장해 한 곳에서 관리한다.
- **주의**: 브라우저 데이터 삭제나 시크릿 모드에서는 기록이 사라진다. `navigator.storage.persist()` 로 영구 저장을 요청하고, 2단계에서 기록 내보내기/가져오기(JSON 백업)를 검토한다.

### ADR-016. 배포는 GitHub Pages + PWA
- **배경**: 휴대폰과 PC 어디서든 열 수 있어야 하고, 개발이 멈춰도 동작해야 한다 (11/11 요청 2절).
- **대안**: (1) 로컬 개발 서버만, (2) GitHub Pages, (3) Netlify/Vercel.
- **결정 근거**: 정적 파일만 있으면 되므로 서버가 필요 없다. PWA(서비스 워커)로 만들면 한 번 연 뒤에는 오프라인에서도 동작하고 홈 화면에 설치할 수 있다. 저장소와 같은 곳에서 관리하므로 추가 계정이 필요 없다.
- **확인 필요**: 저장소가 현재 비공개다. 무료 계정의 GitHub Pages 는 공개 저장소만 지원한다 (GitHub Pro, 학생용 Education 혜택이 있으면 비공개도 가능). 공개로 바꿀 경우 커밋된 파일에 개인정보가 없는지 먼저 점검해야 한다. 단어 원본 데이터는 이미 `.gitignore` 대상이다.

### ADR-017. 앱과 웹을 브랜치로 분리하고 worktree 로 동시에 작업 (2026-11-25 사용자 결정)
- **배경**: 앱과 웹을 둘 다 계속 가져가기로 함. 두 프로젝트를 섞지 않고 따로 작업할 공간이 필요함.
- **대안**: (1) 포크: GitHub 은 자기 저장소를 같은 계정으로 포크할 수 없고, 포크는 남의 저장소에 기여하는 용도. (2) 저장소 분리: 완전 독립이지만 이슈·문서·이력이 둘로 쪼개짐. (3) 한 브랜치에 `web/` 과 앱 코드 공존: 할 일은 없지만 섞여서 혼동됨. (4) 브랜치 + worktree.
- **결정**: (4). `main` = 웹 앱 + 모든 문서 (`C:\dev\smart-voca`), `android` = 앱 코드 (`C:\dev\smart-voca-android`, `android-final` 에서 시작). main 에서는 안드로이드 파일을 지움.
- **결정 근거**: 저장소·이슈·이력은 하나로 두면서 폴더 단위로 독립 작업이 된다. 브랜치 전환 없이 두 폴더를 오가면 된다.
- **운영 규칙**: 문서는 main 에서만 고친다. 공통 규칙은 main 설계 문서에 먼저 적고 양쪽 코드에 반영한다. 도메인 규칙 파일은 `web/src/domain/*.ts` ↔ `android` 의 `domain/*.kt` 로 1:1 대응한다.

### ADR-018. 배포 단계: 임시 동사 묶음, 설정 숨김, 카드 따라 쓰기 학습 (2026-11-25 사용자 결정)
- **배경**: 공개 배포본을 처음 여는 사람도 바로 학습할 수 있어야 함. 단어 데이터 원본은 라이선스 미확인이라 배포할 수 없음 (RK-01).
- **결정**:
  1. **임시 단어 묶음**: 직접 작성한 일상 동사 120개 (`web/public/starter_verbs.csv`, 기초·중급·심화 각 40, 100% 동사, 예문 49개는 직접 쓴 예문 초안에서). DB 가 비어 있을 때만 자동으로 넣는다. 생성 스크립트 `ai-agent/scripts/261125-make_starter_verbs.py`.
  2. **설정 숨김**: `web/src/appConfig.ts` 의 `SHOW_SETTINGS = false`. 설정·가져오기 코드는 유지. 일일 개수는 기본값 10.
  3. **카드 학습** (기존 "목록 + 학습 완료 버튼" 대체): 오늘 목록을 카드 한 장씩 보여 준다. 카드에 뜻, 영단어 가이드, 빈칸 2개. 첫 칸이 맞아야 둘째 칸이 열리고, 두 칸이 모두 맞으면 학습 완료 기록 (FR-020) 후 0.7초 뒤 다음 카드. 대소문자·앞뒤 공백 무시. 정답 길이 전에는 틀림 표시 안 함. 모두 끝나면 완료 화면과 시험 연결.
  4. **QR 코드**: 배포 주소 QR 을 화면 아래에 표시 (`web/public/qr-smart-voca.svg`). 공유용 PNG 는 `ai-agent/claude/261125_웹전환/smart-voca-qr.png`.
- **해석한 부분**: "가이드에 따라" 를 "카드에 보이는 영단어를 보고 따라 쓰기" 로 구현 (빈칸 안에도 흐린 글자로 표시). 다르게 의도했다면 바꾼다.
- **요구사항 영향**: FR-040~045 (설정) 는 숨김 상태. 학습 완료 판정 방식이 바뀌므로 요구사항 명세서 갱신 필요 (6단계).

### 유지되는 결정
ADR-004~010, ADR-012, ADR-013 은 플랫폼과 무관하므로 그대로 유지한다. ADR-011 (Compose 상태로 화면 구현) 은 "React 상태(`useState`)로 화면 구현, 공용 로직은 `domain/` 함수로 분리" 로 바꿔 적는다.

## 3. 이관 범위 (Kotlin → TypeScript)

규칙(도메인)과 테스트는 1:1 로 옮기고, 화면과 저장 코드는 웹 방식으로 새로 쓴다.

| 기존 Kotlin 파일 | 새 TypeScript 파일 (`web/src/`) | 이관 방식 |
|------------------|----------------------------------|-----------|
| `domain/FunctionWords.kt` | `domain/functionWords.ts` | 그대로 옮김. `function_words.csv` 는 `web/public/` 로 복사 |
| `domain/DailyWordSelector.kt` | `domain/dailyWordSelector.ts` | 그대로 옮김 |
| `domain/StageRules.kt` | `domain/stageRules.ts` | 그대로 옮김 (재노출 1·3·7·14·30일) |
| `domain/ExamRules.kt` | `domain/examRules.ts` | 그대로 옮김 |
| `data/csv/CsvRecordReader.kt`, `WordCsvParser.kt` | `data/csv/wordCsvParser.ts` | 그대로 옮김. 파일 읽기는 `<input type="file">` 로 대체 |
| `data/db/*Entity.kt`, `SmartVocaDatabase.kt` | `data/db.ts` | Dexie 테이블 정의로 새로 작성 (`words`, `dailyWords`, `examAttempts`, `settings`) |
| `data/WordRepository.kt`, `DailyListRepository.kt`, `StudyRepository.kt`, `ExamRepository.kt` | `data/*Repository.ts` | 함수 이름과 역할 유지, 내부는 Dexie 로 새로 작성 |
| `data/SettingsStore.kt` | `data/settingsStore.ts` | 범위 밖 값은 기본값으로 읽는 규칙 유지 |
| `MainActivity.kt` | `App.tsx`, `main.tsx` | 화면 전환과 날짜 변경 팝업 |
| `ui/TodayWordScreen.kt`, `ExamScreen.kt`, `SettingsScreen.kt`, `ImportScreen.kt` | `ui/TodayWordScreen.tsx` 등 | 새로 작성. 색은 ADR-013 팔레트를 CSS 변수로 옮김 |
| `src/test/**/*Test.kt` | `web/src/**/*.test.ts` | Vitest 로 같은 테스트 케이스를 옮김 |

**테스트 방법 (예정)**: `cd web && npm test` (Vitest), 실행 `npm run dev`, 배포용 빌드 `npm run build`.
