# Smart Voca 시스템 아키텍처 설계서

**파일 위치**: `ai-agent/claude/261021_아키텍처설계서.md`
**작성일**: 2026-10-21
**버전**: v1.0 (초안)
**설명**: 스마트보카 안드로이드 앱의 구성 요소, 계층, 데이터 흐름을 정의한다. 요구사항 명세서 v1.0 과 작업 계획 v1.0 을 기준으로 한다.

---

## 1. 구조 개요

- 서버 없이 기기 내에서 동작하는 단일 안드로이드 앱 (NFR-001, NFR-005)
- 언어와 UI: Kotlin, Jetpack Compose (ADR-001)
- 저장: Room (SQLite) 로 학습 데이터, DataStore 로 설정 (ADR-002, ADR-003)
- 최소 지원 버전: Android API 26 (NFR-007, OI-09 확정)

### 1.1 계층 구성

| 계층 | 구성 요소 | 책임 |
|------|----------|------|
| UI | `TodayWordScreen`, `ExamScreen`, `SettingsScreen`, `ImportScreen` | 화면 표시와 사용자 입력 |
| ViewModel | `TodayWordViewModel`, `ExamViewModel`, `SettingsViewModel`, `ImportViewModel` | 화면 상태 관리, 도메인 호출 |
| 도메인 | `DailyWordSelector`, `ReviewScheduler`, `ExamGenerator`, `ExamGrader` | 선정, 재노출, 시험 출제와 채점 규칙 |
| 데이터 | `WordRepository`, `StudyRepository`, `ExamRepository`, `SettingsStore` | 저장소 접근 캡슐화 |
| 저장 | Room DAO (`WordDao`, `DailyListDao`, `ReviewDao`, `ExamDao`), DataStore | 물리 저장 |
| 입력 | `CsvWordLoader` | CSV 파싱, 검증, 적재 요청 |

### 1.2 의존 방향

UI → ViewModel → 도메인 → 데이터 → 저장. 역방향 의존은 두지 않는다. 도메인 계층은 Android 프레임워크에 의존하지 않도록 하여 단위 테스트를 쉽게 한다.

## 2. 주요 흐름

### 2.1 CSV 가져오기 (FR-001~005)
1. 사용자가 `ImportScreen` 에서 파일을 고른다.
2. `CsvWordLoader` 가 헤더를 검사한다. 필수 열이 없으면 중단한다 (FR-002).
3. 행을 파싱하고 필수 값과 형식을 검증한다. 실패 행은 번호와 사유를 모은다 (FR-003).
4. `WordRepository` 가 `freq_rank` 기준으로 저장한다 (같은 순위는 갱신, FR-004 는 품사 확보 후 적용).
5. 가져오기 결과(성공, 건너뜀 개수와 목록)를 화면에 보여 준다.

### 2.2 오늘의 단어 (FR-010~015)
1. `TodayWordViewModel` 이 열릴 때 오늘 날짜의 목록이 있는지 확인한다.
2. 없으면 `DailyWordSelector` 가 목록을 만든다 (프로세스 설계서 P2).
3. 학습 완료 처리 시 `StudyRepository` 가 학습 기록과 재노출 일정을 저장한다 (P3).

### 2.3 시험 (FR-031, 033, 035~038)
1. `ExamViewModel` 이 `ExamGenerator` 에게 출제 대상을 요청한다. 대상은 오늘 목록과 재노출 대상이다.
2. 사용자가 뜻을 보고 영단어를 입력하면 `ExamGrader` 가 채점한다.
3. `ExamRepository` 가 시험 이력을 저장한다. 재노출 일정은 바꾸지 않는다 (FR-037).

### 2.4 설정 (FR-040~045)
- `SettingsStore` 가 DataStore 에 값을 저장한다. 값 범위는 `SettingsViewModel` 에서 검증한다.

## 3. 저장 구성

| 저장소 | 내용 | 기술 |
|--------|------|------|
| Room DB | 단어, 일일 목록, 학습 기록, 재노출 일정, 시험 이력 | SQLite (Room) |
| DataStore | 일일 개수, 난이도, 동사 비중 (저장만), 시험 문제 수 | Preferences DataStore |

자세한 테이블 정의는 데이터 설계서를 따른다.

---

## 4. 외부 연동

- 없음. 인터넷 권한을 요청하지 않는다 (NFR-005, 제안).
- 단어 데이터는 사용자가 기기에서 고른 CSV 파일로만 들어온다. 앱에 번들하지 않는다 (ADR-005).

## 5. 비기능 설계 대응

| 요구사항 | 대응 |
|----------|------|
| NFR-001 오프라인 | 외부 연동 없음 |
| NFR-002 영구 저장 | Room, DataStore |
| NFR-003 CSV 30초 이내 | 한 번의 트랜잭션으로 일괄 저장 |
| NFR-004 목록 생성 1초 이내 | `freq_rank` 와 `level` 인덱스 사용 |
| NFR-010 파일 크기 | 파일당 500줄 기준 분리 |
