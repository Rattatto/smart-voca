# Smart Voca 아키텍처 결정 기록 (ADR)

**파일 위치**: `ai-agent/claude/Smart_Voca_Decision_Records_v1.0_261021.md`
**작성일**: 2026-10-21
**버전**: v1.0 (초안)
**설명**: 프로젝트의 기술 선택과 방침 결정을 배경, 대안, 결정 근거 형식으로 남긴다. 되돌아볼 가능성이 있는 결정만 기록한다.

---

## ADR-001. 안드로이드 네이티브 (Kotlin, Jetpack Compose)

- **상태:** 승인 (261021)
- **배경:** 대상 플랫폼은 안드로이드 앱이다 (기획서 §1). 학습 과제이므로 구조를 명확히 보여 줄 수 있어야 한다.
- **대안:** Flutter, React Native (크로스 플랫폼)
- **결정 근거:** 대상이 안드로이드 하나이므로 크로스 플랫폼의 이점이 없다. Compose 는 선언형 UI 로 화면 상태 관리를 단순하게 만든다.

## ADR-002. 로컬 저장은 Room (SQLite)

- **상태:** 승인 (261021)
- **배경:** 서버가 없고 학습 기록과 시험 이력을 앱에 영구 저장해야 한다 (NFR-002).
- **대안:** 파일 저장 (JSON), 직접 SQLite 접근
- **결정 근거:** 관계형 데이터(단어, 일정, 기록)를 다루므로 SQLite 가 맞다. Room 은 컴파일 시점에 쿼리를 검사하고, 마이그레이션을 관리한다.

## ADR-003. 설정 저장은 DataStore

- **상태:** 제안 (구현 시작 시 확정)
- **배경:** 일일 개수, 난이도 같은 작은 설정 값을 저장한다.
- **대안:** SharedPreferences
- **결정 근거:** DataStore 는 비동기 API 를 제공하고 SharedPreferences 의 동기 호출 문제를 피한다. 신규 프로젝트에서 권장되는 방식이다.

## ADR-004. 1차 시험은 뜻 보고 영단어 입력 (빈칸 문장은 2차)

- **상태:** 승인 (261021, 사용자 결정)
- **배경:** 빈칸 문장 시험에 필요한 예문과 품사가 원본 데이터에 없다 (OI-12, OI-13).
- **대안:** (A) 뜻 보고 영단어 입력, (B) 영단어 보고 뜻 4지선다, (C) 뜻 보고 영단어 4지선다. 빈칸 문장 시험을 1차에 유지하는 방법은 예문을 새로 만드는 것인데 보류됨.
- **결정 근거:** A 는 현재 데이터만으로 구현 가능하고 입력형이라 찍기가 어렵다. 사용자가 A 를 선택했다. 빈칸 문장 시험은 예문이 확보되면 2차에 추가한다.

## ADR-005. 단어 데이터는 사용자가 가져오는 CSV 로 로드하고 앱에 번들하지 않음

- **상태:** 승인 (261021, 사용자 결정 2번 방침)
- **배경:** 원본 PDF 의 출처는 개인 블로그이고 라이선스가 확인되지 않았다 (OI-10).
- **대안:** 앱에 단어 데이터를 포함해 배포
- **결정 근거:** 라이선스가 확인되기 전까지 배포 가능한 형태로 만들지 않는다. CSV 가져오기 방식은 데이터 교체도 쉽다 (BR-07). 개인 학습용 로컬 테스트에서는 사용할 수 있다.

## ADR-006. 기기 내장 LLM (Gemini Nano) 기능은 1차에서 제외

- **상태:** 승인 (261021, 사용자 결정 보류)
- **배경:** 갤럭시 S26 의 Gemini Nano 지원 여부가 자료마다 엇갈린다. 기능 추가 시 1~3주 기간 증가가 예상된다.
- **대안:** 1차에 포함, 검증 실험 후 포함 여부 결정
- **결정 근거:** 1개월 일정과 1인 개발 조건에서 위험이 크다. 2차에서 기기 검증부터 시작한다.

## ADR-007. 난이도는 빈도 순위 구간으로 정함

- **상태:** 승인 (261021, OI-03, OI-11)
- **배경:** 원본에 난이도 열이 없다. 원본은 빈도 순위로 정렬되어 있다.
- **대안:** 단어 길이, 뜻 개수, 별점 기준
- **결정 근거:** 빈도 순위는 일상 사용 빈도와 가장 직접 관련된다. 구간은 1~1000 기초, 1001~3000 중급, 3001~5000 심화로 정했다 (OI-11).

## ADR-008. 별점은 원문 그대로 저장

- **상태:** 승인 (261021, 사용자 결정). 기호 의미는 미정 (OI-14)
- **배경:** 원본에 별점 표기(★, ☆, △)가 있다. 사용자가 세부 규칙에 반영할 수 있도록 우선 추가하라고 했다.
- **대안:** 별 개수 정수로 변환, 기호 의미를 추정해 변환
- **결정 근거:** `△` 의 의미가 확인되지 않았다. 추정으로 바꾸면 정보가 손실되므로 원문을 보존한다. 의미가 확정되면 정수 열을 추가한다.

## ADR-009. 품사와 예문은 확보 전까지 비워 둠

- **상태:** 승인 (261021, 사용자 결정 보류)
- **배경:** 원본에 품사, 예문이 없다. 제가 임의로 채우면 검수되지 않은 데이터가 섞인다.
- **대안:** 제가 품사와 예문을 생성, 외부 데이터 사용
- **결정 근거:** 사용자가 데이터 확보 또는 자체 생성 가능 시점에 알려 주기로 했다. 그때까지 동사 비중 기능(FR-012, FR-032)과 빈칸 시험(2차)은 보류한다.
